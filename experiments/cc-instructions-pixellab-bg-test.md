# Claude Code Instructions: PixelLab Background Stress Test

## Context

This is a visual quality validation test for Two Fires (repo: ~/giants-drink). We need to determine whether PixelLab can generate backgrounds (parallax layers) at a quality level comparable to 16-bit SNES games. This is the single most important visual question in the project right now.

Read claude.md and docs/current-status.md first. The PixelLab MCP integration is already configured.

## Goal

Build a **single self-contained HTML file** (Phaser 3 via CDN) that is a playable sidescroller test scene. EVERY visual asset in the scene must be generated by PixelLab during this session. The scene should demonstrate:

1. Multi-layer parallax backgrounds (3-4 layers at different scroll speeds)
2. A tileset for the ground/platforms the player walks on
3. A player character that moves and jumps
4. One enemy that patrols
5. A few decorative map objects (crates, pipes, machinery)
6. All of it rendered together in Phaser 3 with parallax scrolling

The theme is: **Industrial/mechanical, 16-bit SNES style** (think Mega Man X factory stage, or a gritty machine-filled facility). Rich colors, detailed shading, atmospheric depth.

## Step-by-Step Plan

### Phase 1: Generate Background Layers (parallax)

We need 3-4 horizontally tileable background layers. Generate them using PixelLab. The strategy for backgrounds:

**Layer 1 (furthest — sky + distant):** Use `Create map (pixflux)` or `Create M-XL image` at ~400x200 resolution, sidescroller view. Prompt: "Distant industrial cityscape silhouette against dark blue night sky with smog and faint stars, 16-bit SNES pixel art style, atmospheric perspective, suitable for parallax background layer". This should be relatively simple/flat — it's the furthest layer.

**Layer 2 (mid-far — buildings/smokestacks):** Same tool, ~400x200. Prompt: "Mid-ground industrial factory buildings with smokestacks and steam pipes, dark metal and orange lit windows, 16-bit SNES pixel art, medium detail, parallax background layer". More detail than layer 1 but still background.

**Layer 3 (mid-near — machinery):** Same tool, ~400x200. Prompt: "Near-ground heavy machinery, gears, conveyor belt structures, metal scaffolding, industrial pipes with steam, 16-bit SNES pixel art, detailed shading, foreground parallax layer". This layer has the most visual detail.

**IMPORTANT for all background layers:**
- Request NO transparent background (these are full-scene layers)
- Target palette: industrial (dark blues, grays, oranges, warm highlight accents)
- Each layer needs to tile horizontally. If the create-map tool doesn't produce tileable output, use "Create texture" tool instead, which is designed for tileability.
- Keep consistent art style across all layers (use same detail/shading/outline settings)
- If results aren't good on first try, iterate the prompts. Try different tools (pixflux map vs. M-XL image vs. texture). The goal is QUALITY, not speed.

**Alternative approach if map tool produces poor backgrounds:** Use PixelLab's "Create M-XL image (new)" tool (PixFlux model) with explicit prompts describing parallax-style background art. This is the general-purpose image generator and may give better results for scenic backgrounds than the map tool, which is optimized for top-down/playfield views.

**Another alternative:** Generate a single wide scene (~400x200) and then manually split it into depth layers by generating variations — one with only distant elements, one with mid-ground, one with near-ground. Each generation uses the previous as an init image with inpainting.

Try the most straightforward approach first. If quality is poor, try alternatives before moving on.

### Phase 2: Generate Platform Tileset

Use `create_sidescroller_tileset` MCP tool:
- lower: "dark industrial metal floor with rivets and grating"  
- transition: "rust and oil stains"
- Style: highly detailed shading, 16-bit

This gives us the ground tiles the player walks on.

### Phase 3: Generate Character

Use `create_character` MCP tool:
- description: "armored soldier with visor helmet and pulse rifle, 16-bit SNES style, sci-fi industrial"
- n_directions: 2 (east/west is sufficient for sidescroller)
- Then `animate_character` for walk cycle

### Phase 4: Generate Enemy

Use `create_character` MCP tool:
- description: "small hovering patrol drone with red sensor eye, industrial robot, 16-bit SNES pixel art"
- n_directions: 2
- Then animate idle/patrol

### Phase 5: Generate Decorative Objects

Use `create_map_object` MCP tool for 3-4 objects:
- "metal crate with hazard stripes, industrial, 16-bit pixel art"
- "steam pipe with valve, leaking steam, industrial, 16-bit"  
- "wall-mounted warning light, red glow, industrial"
- "broken conveyor belt segment, rusted metal, industrial"

### Phase 6: Assemble Phaser Scene

Build a single HTML file (save to ~/giants-drink/experiments/pixellab-bg-test/index.html) that:

1. Loads Phaser 3 from CDN
2. Loads all generated PNG assets
3. Creates 3-4 parallax background layers using Phaser's TileSprite at different scroll factors:
   - Layer 1 (sky): scrollFactor 0.1
   - Layer 2 (mid-far): scrollFactor 0.3  
   - Layer 3 (mid-near): scrollFactor 0.6
   - Platform tileset: scrollFactor 1.0 (normal)
4. Builds a simple ground platform with the tileset
5. Places character with left/right/jump controls (arrow keys)
6. Places enemy with simple patrol (walks back and forth)
7. Places decorative objects on/near platforms
8. Camera follows player, which drives the parallax effect
9. The level should be at least 3-4 screens wide so parallax scrolling is visible

**Phaser parallax setup pattern:**
```javascript
// In create():
this.bg1 = this.add.tileSprite(0, 0, config.width, config.height, 'bg-layer1')
  .setOrigin(0, 0).setScrollFactor(0);

// In update():
this.bg1.tilePositionX = this.cameras.main.scrollX * 0.1;
this.bg2.tilePositionX = this.cameras.main.scrollX * 0.3;
this.bg3.tilePositionX = this.cameras.main.scrollX * 0.6;
```

### Phase 7: Visual Quality Assessment Page

In addition to the playable scene, create a simple HTML page (experiments/pixellab-bg-test/assets.html) that shows:
- Each background layer individually, at full resolution
- The tileset
- All sprites/objects
- A side-by-side composite showing all layers stacked

This lets Joe evaluate each asset individually AND in composition.

## Important Notes

- PixelLab jobs are async. Queue them in parallel where possible (characters, backgrounds, objects can all be requested simultaneously). Poll for completion.
- Save ALL generated assets to experiments/pixellab-bg-test/assets/ with descriptive names (bg-layer1-sky.png, bg-layer2-buildings.png, etc.)
- If a PixelLab generation looks bad (you can see the returned image), try regenerating with adjusted prompts before accepting it. Quality is the whole point of this test.
- Use consistent PixelLab settings across all generations: "highly detailed shading", "single color outline" or "selective outline", high detail level
- Target a SNES-like color palette: NOT oversaturated. Rich but grounded. Dark blues, steel grays, warm orange accents, some green/teal for contrast.
- The HTML files should work when opened directly in a browser (file:// protocol) — embed assets as base64 or use relative paths to the assets/ folder.
- If Phaser complains about CORS with local files, that's fine — Joe can serve it locally or it can be deployed to Vercel later. Just make sure the code is correct.
- Game canvas size: 480x270 (SNES resolution) scaled up 2-3x for display. This gives us the authentic SNES pixel density.

## Success Criteria

Joe will look at the result and answer one question: "Does this look like it could be a real SNES game, or does it look AI-generated?"

That's the whole test. Don't optimize for anything else. Visual quality of the COMPOSED SCENE is everything.
